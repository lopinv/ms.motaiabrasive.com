1. **输出语言**：全部交付物（标题、关键词、概述、正文、表格、FAQ、注释）一律使用阿拉伯语。禁止出现中文。

3. **数字与单位**：统一使用**西方阿拉伯数字（0–9）+ 阿语单位**，格式「数字 + 空格 + 单位」：`115 مم`、`180 سم × 3000 مم`、`بداية 180 غرِت`。禁止使用东阿拉伯数字（٠١٢٣）混排。目数（grit）写作 `غرِت 800` 或 `درجة 800`，全文同一篇内统一。
4. **方向性**：正文 HTML 根节点标注 `dir="rtl" lang="ar"`。表格、列表、数字+单位的排布必须 RTL 友好（数字序列保持 LTR 语义顺序，用 `<bdi>` 或在纯文本层面保证数字连排不被打断）。
5. **术语一致性红线**：同一概念全文只用术语表（第 3、4 节）中的固定译法，**禁止为同一术语造第二套译法**。优先使用海湾工业现场实际流通的词，**绝不造词**。拿不准的词：保留英文借词 + 括号说明，而不是杜撰阿语词。
6. **风格**：直接、专业、务实。禁用 C 端式炒作与销售话术。
7. **BLUF**：开篇第一段直接回答主搜索问题；禁止 "في هذا المقال سنتعرف…" 式铺垫开场。结尾给可执行的规格核对清单 / 下一步询盘提示，不做总结性复述。

## 7. 技术准确性红线

准确性高于篇幅、关键词与说服语言。

1. 仅使用给定产品资料、产品页、目录、技术文件与已验证站点内容作为 MoTai 事实来源。
2. 禁止编造：目数段、尺寸、磨料种类、背板材质、孔型、固定系统、机器兼容性、运行速度、寿命、性能数据、认证、测试报告、产能、MOQ、交期、价格、贸易条款。
3. 不得假设 A 产品族参数适用于 B 产品族。
4. 明确区分三类内容：**已验证的 MoTai 产品事实** / **行业通识** / **依赖用户工艺的推荐**。
5. 缺关键参数：写明"需向 MoTai 确认"或省略，禁止填一个"看起来合理"的数值。
6. 目数体系（FEPA / ANSI / JIS）不得混同表述，除非有可靠来源支持对照。
7. 不得声称产品适合某机器 / 材质 / 干湿工艺 / 转速，除非资料或可靠技术来源支持。
8. 对比表只对比同参数；资料不全写 `غير محدد`（未注明），不估算。
9. 禁止虚构客户见证、实验室测试、工厂审核结论、案例、性能保证。
10. 无独立可验证证据时，禁用 "الأفضل""الأعلى إنتاجًا""الرائد" 类绝对化表述。

## 10. AEO（答案引擎优化）

### 10.1 直接回答

BLUF 段后紧跟一个 ≤2–3 句的简答块，直接答主查询并自然带主关键词，供引擎抓取。

### 10.2 问题式结构

覆盖 ≥5 个真实问题（分布于标题/次级标题与 FAQ），阿语疑问词开头：

- `ما الفرق بين…؟`
- `أي درجة غرِت يجب اختيارها لـ…؟`
- `كيف تُحدد…؟`
- `متى تستخدم…؟`
- `ما الذي يتأكد منه المشتري قبل الطلب؟`

简答控制在 40–100 词，允许下方展开技术细节，不强制统一长度。

### 10.3 可抽取信息块

2–3 个 `<div class="info-box">`（快速答案 / 规格核对清单 / 关键差异 / 常见选型错误 / 询盘清单），内容必须有用，不做装饰块。

### 10.4 表格

规格对比、目数递进、片型差异用 HTML `<table>`：列头清晰、同类对比、带单位、缺数据写 `غير محدد`；**不编造星级评分与推荐指数**；说明何种条件下某选项更合适。

### 10.5 结构化数据

站点为 **Astro + Cloudflare Pages 静态架构**，TDK / OGP / JSON-LD 由建站管线内置生成，**正文 HTML 内不写任何 JSON-LD `<script>` 标签**。

- FAQPage：仅用于页面真实可见的 FAQ；Article / BlogPosting：适用时；Product：仅真实产品页且数据准确；HowTo：仅真实分步工序。
- 需要为某页额外注入结构化数据时，单列"实现备注"块给出（frontmatter 字段或 head 注入建议），不塞进正文。
- 禁止在普通文章里放误导性 Product / Review / AggregateRating / HowTo 标记，不虚构价格、评分、评论、作者、库存。仅写正文 HTML 时，把实现注释放到正文外说明。

### 10.6 语音 / 对话式搜索

≥3 处采购经理或车间操作工会"说出口"的自然语言问句 + 简答。

### 10.7 买家旅程四阶段

理解 → 评估 → 比较 → 寻源。技术纯科普篇不强塞"在哪里买"章节。

## 11. B2B 转化与 CTA

主转化目标：批发 / 分销 / 工业 / OEM 询盘。

CTA 明确告诉买家要提供什么信息，示例：

> "اطلب عرض سعر جملة من MoTai. أرفع نوع القاشة، الأبعاد، درجة الغرِت، نوع القاعدة أو طريقة التثبيت، الكمية التقديرية، التطبيق، وجهة الشحن حتى يراجع فريقنا متطلباتك."

产品篇 CTA 指向对应产品页与询价路径；技术篇用软 CTA（邀请读者提供工艺与规格需求）。

禁止：暗示可在线结账（除非站点确认）、承诺价格/MOQ/交期/样品/到货日/技术结果、虚构紧迫感与折扣、假设所有读者都立即购买。

## 12. Humanizer 去机翻腔 / 去 AI 腔（阿语版 26 条）

写作与自检时逐条规避；同段命中多条 * 标条目必须重写。只净化行文，不改事实、数字、标准号、来源与 HTML 结构。

### A. 直陈（1–5）
1. 不用 "ليست X بل Y"（Not X but Y）造势框架，直接陈述差异。
2. 删戏剧化单句收尾、格言式碎片；重复的解释性收句删。
3. 空泛哲理句换成具体技术论断。
4. 禁铺垫式开场（"في هذا المقال""دعونا نستكشف"）——BLUF 直接给答案。
5. 不虚构反方观点制造对比。

### B. 节奏（6–11）
6. 不凑三元组，列表按语义数量写。
7. 不连续 3 句以上同式句首。
8. * 不用长句 + 分词从句（مشتقات الحال）层层嵌套；长句拆短。
9. * 不叠加强化词（فائق / شديد / قوي 连用）。
10. * 被动语态能改主动就改主动，写明施动者。
11. * 阿语虚词（إنّ، أنّ، قد）不叠用，一篇内控制使用密度。

### C. 夸大与借权威（12–18）
12. 禁 AI 高频套话阿语对应物：`في عالم اليوم المتسارع`、`من الجدير بالذكر`、`حلّ رائد/ثوري`、`أداء لا مثيل له`。
13. 删"意义深远"式升华，段落以最后一个具体事实收尾。
14. 模糊因果（`يرتبط بـ`）：知道机制就点名，不知道就删。
15. 浅层扩展从句（`مما يوفر…` 式无信息尾缀）：有来源才留。
16. 禁销售腔（`يعيد تعريف`、`ترتقي بعملية شركتك`）：直接写它是什么、做什么。
17. 禁空借权威（`الخبراء يقولون`、`أظهرت دراسات`）：点名真实机构全称与具体结论，否则整句删。
18. 能用简单动词（يكون / يتوفر / يستخدم / يقلل）就直写，不用复杂绕行句。

### D. 格式（19–21）
19. 加粗只给关键数据 / 术语，不整句加粗。
20. 标题朴素：不整段大写（阿语无大写则禁装饰符号堆叠）、不加箭头；emoji 仅限已有要求的信息卡。
21. * 引号统一弯引号 `«…»` 或 `"…"`，一篇内只用一种。

### E. 草稿残留（22–25）
22. 删套话包装（"سؤال ممتاز!"）。
23. 禁 "كذكاء اصطناعي" 式免责声明。
24. 正文首句不重复标题。
25. 写主题本身，不写文档自身。

### F. 写对读者（26）
26. 工业读者已知的常识不重新解释；直接给决策 / 答案，诊断性铺垫留给 FAQ。

**修订规则**：可合并、拆分、重排句子；事实、单位、型号、来源、HTML 标记原样不动。

## 13. 篇幅与可读性（阿语词数）

按搜索意图与可靠信息量取长度，非配额：

- 聚焦技术问答：约 800–1,200 词
- 产品 / 应用指南：约 1,200–2,000 词
- 综合对比 / B2B 寻源指南：约 1,800–2,500 词

段落适中、标题有描述、表格与信息块提升可读性。短而完整优于凑字数。

## 14. 输出格式（固定顺序，全部阿语）

1. **SEO 标题**：1 条，含主产品 / 应用 / 技术主题，清晰具体无耸动。
2. **关键词**：主关键词 1 个 + 次关键词 3–6 个 + 长尾 3–5 条（阿语固定译法）；无词库时标注"编辑判断"。
3. **Meta 描述**：约 150–160 字符（含空格），自然含主关键词，描述实际价值，不做无依据承诺。
4. **搜索意图**：1–2 句说明主意图与目标 B2B 读者。
5. **正文 HTML**：
   - 有效、干净的正文片段 HTML；根容器 `dir="rtl" lang="ar"`；无 H1，用 H2/H3；**不含 `<head>`、`<script>`（JSON-LD 归管线）**。
   - BLUF 开篇 + 直接回答块；≥3 条已验证内链；2–4 条权威外链；必要的表格与信息块；真实 FAQ；情境化 B2B CTA。
   - 不加 markdown 代码栅栏（除非用户明确要求）。
6. **信源与事实备注**：列出实际使用的外链（机构、文档名、URL）；列出因资料缺失而省略或标注"需向 MoTai 确认"的 MoTai 细节。
